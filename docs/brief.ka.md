# პროექტი „ანბანი“ — ციფრული ბიბლიოთეკა გამოწერით

### ტექნიკური დავალება (ბრიფი) ფრონტენდ-დეველოპერებისთვის · STEP IT Academy

> **როლი:** თქვენ ხართ ციფრული სააგენტოს ფრონტენდ-დეველოპერი.
> **კლიენტი:** სტარტაპი „ანბანი“, რომელიც საქართველოში იწყებს წიგნების გამოწერის სერვისს — ერთი გამოწერა, მთელი ბიბლიოთეკა.

## 1. კლიენტის ბრიფი

> „გვინდა, ადამიანებმა ქართული და მსოფლიო კლასიკა ბრაუზერიდან, ნებისმიერი მოწყობილობიდან წაიკითხონ. ბიზნეს-მოდელი მარტივია: **7 დღე უფასოდ, შემდეგ თვიური ან წლიური გამოწერა.** სტუმარს უნდა შეეძლოს კატალოგის დათვალიერება და ყოველი წიგნის ფრაგმენტის წაკითხვა — ასე ვარწმუნებთ, რომ გამოიწეროს. ჩვენს გუნდს სჭირდება ადმინ-პანელიც: წიგნების ატვირთვა, მომხმარებლების მართვა და გაყიდვების ნახვა.
>
> ბექენდი უკვე მზადაა. ჩვენ გვჭირდება ფრონტენდი, რომელიც **დოკუმენტაციის მიხედვით** სწორად იყენებს API-ს და სწორად მართავს ყველა მდგომარეობას: შესული/გასული, დადასტურებული/დაუდასტურებელი, საცდელი/აქტიური/გაუქმებული/ვადაგასული.“

## 2. რას ისწავლით

ამ პროექტის ბოლოს შეძლებთ:

1. **დოკუმენტაციის წაკითხვას** — ენდპოინტი, მეთოდი, ჰედერები, request/response, შეცდომები — და მის მიხედვით კოდის დაწერას.
2. **ორდონიან ავტორიზაციას** — API გასაღები (აპლიკაცია) + JWT (მომხმარებელი); access/refresh ტოკენები, ავტომატური განახლება interceptor-ით.
3. **მდგომარეობების მართვას** — ერთი და იგივე გვერდი სხვადასხვა მომხმარებლისთვის სხვადასხვანაირად გამოიყურება.
4. **ფორმებს და ვალიდაციას** — კლიენტზე და სერვერზე; სერვერის შეცდომების ველებზე განაწილება.
5. **სიებს** — ძებნა, ფილტრები, სორტირება, პაგინაცია, მდგომარეობა URL-ში.
6. **გადახდის ნაკადს** — ბარათის ფორმა, უარყოფის სცენარები, ორმაგი გადახდის თავიდან აცილება.
7. **ფაილებთან მუშაობას** — PDF-ის ჩვენება, ფაილის ატვირთვა `FormData`-ით.
8. **ადმინ-პანელის აწყობას** — CRUD, ცხრილები, სტატისტიკა, როლები.
9. **ხარისხს** — loading/empty/error მდგომარეობები, responsive დიზაინი, ხელმისაწვდომობა (a11y).

## 4. ფუნქციური მოთხოვნები

დონეები: **🟢 MVP** (სავალდებულო) · **🟡 გაფართოებული** (სავალდებულო მაღალი ქულისთვის) · **🔴 ადმინ-პანელი** · **⭐ ბონუსი**

### 4.1 🟢 კატალოგი და წიგნი

**US-1. როგორც სტუმარს, მინდა წიგნების კატალოგის დათვალიერება.**
- [ ] წიგნები ბარათებად: ყდა (`coverUrl`), სათაური, ავტორი, რეიტინგი, გვერდები; ბეჯები „უფასო“ (`isFree`) და „ახალი“ (`isNew`)
- [ ] ძებნა სათაურით/ავტორით (`q`) — debounce-ით
- [ ] ფილტრი კატეგორიით (`GET /api/categories`) და ენით (`language`)
- [ ] სორტირება (`sort`: popular, rating, newest, title)
- [ ] პაგინაცია (`page`, `pageSize`, `totalPages`) — ნუმერაციით ან „მეტის ჩატვირთვით“
- [ ] ფილტრები ინახება URL-ში: გვერდის განახლების შემდეგ იგივე სია ჩანს
- [ ] skeleton ჩატვირთვისას; ცარიელი შედეგი — „ვერაფერი მოიძებნა“ + ფილტრების გასუფთავება; შეცდომა — „თავიდან ცდა“

**US-2. როგორც მკითხველს, მინდა წიგნის გვერდზე ყველა ინფორმაციის ნახვა.**
- [ ] `GET /api/books/{id}`: აღწერა, ავტორი, წელი (`yearLabel`), გვერდები, კითხვის დრო (`readingMinutes`), ენა, კატეგორია, თეგები
- [ ] სარჩევი (`chapters`)
- [ ] რეიტინგი და განაწილება (`ratingBreakdown`) — ჰისტოგრამა
- [ ] **მთავარი ღილაკი იცვლება `access.reason`-ის მიხედვით** (იხ. ცხრილი §5)
- [ ] „ფრაგმენტი“ ყველასთვის (`previewUrl`)
- [ ] მსგავსი წიგნები (`/related`)
- [ ] არარსებული id → 404 გვერდი

### 4.2 🟢 ავტორიზაცია

**US-3. როგორც სტუმარს, მინდა რეგისტრაცია და შესვლა.**
- [ ] რეგისტრაციის ფორმა: სახელი, გვარი, ელ-ფოსტა, პაროლი (+ ჩვენება/დამალვა)
- [ ] კლიენტის ვალიდაცია **და** სერვერის `errors`-ის ჩვენება შესაბამისი ველის ქვეშ
- [ ] `409 EMAIL_TAKEN` — გასაგები შეტყობინება ელ-ფოსტის ველთან
- [ ] შესვლა; `401 INVALID_CREDENTIALS` — „ელ-ფოსტა ან პაროლი არასწორია“
- [ ] გასვლა (`POST /api/auth/logout` + ლოკალური მონაცემების წაშლა)
- [ ] გვერდის განახლების შემდეგ მომხმარებელი რჩება შესული
- [ ] დაცული გვერდები სტუმარს გადაჰყავს `/login`-ზე, შესვლის შემდეგ კი უკან აბრუნებს (`?next=`)

**US-4. როგორც ახალ მომხმარებელს, მინდა ელ-ფოსტის დადასტურება.**
- [ ] 6-ნიშნა კოდის შეყვანის გვერდი (კარგი UX: 6 ცალკე ველი, ავტომატური გადასვლა, paste-ის მხარდაჭერა)
- [ ] „კოდის თავიდან გაგზავნა“ — 60 წამის ტაიმერით
- [ ] `INVALID_CODE` (+ `attemptsLeft`), `CODE_EXPIRED`, `TOO_MANY_ATTEMPTS`-ის დამუშავება
- [ ] დაუდასტურებელ მომხმარებელს ყველგან ხედავს შეხსენება (ბანერი)

**US-5. როგორც მომხმარებელს, მინდა, 15 წუთის შემდეგ არ „გამაგდოს“.**
- [ ] `401 TOKEN_EXPIRED` → ავტომატური `POST /api/auth/refresh` → მოთხოვნის გამეორება — **მომხმარებლისთვის შეუმჩნევლად**
- [ ] ერთდროული მოთხოვნებისას refresh ერთხელ სრულდება
- [ ] refresh-ის ჩავარდნისას → გასვლა და `/login`

### 4.3 🟢 გამოწერა

**US-6. როგორც მომხმარებელს, მინდა უფასო საცდელი პერიოდის დაწყება.**
- [ ] ფასების გვერდი: გეგმები `GET /api/plans`-დან (ფასი, თვიური ეკვივალენტი, ფუნქციები, „საუკეთესო არჩევანი“ — `isPopular`)
- [ ] ღილაკი „დაიწყე 7 დღე უფასოდ“ ჩანს მხოლოდ მაშინ, როცა `canStartTrial: true`
- [ ] სტუმარს → რეგისტრაციაზე; დაუდასტურებელს → დადასტურებაზე

**US-7. როგორც მომხმარებელს, მინდა გამოწერის ყიდვა.**
- [ ] გადახდის ფორმა: ბარათის ნომერი (4-4-4-4 ფორმატირება), მფლობელი, ვადა MM/YY, CVC
- [ ] კლიენტზე: Luhn-ის შემოწმება, ვადა არ არის წარსულში, CVC 3–4 ციფრი
- [ ] შეკვეთის შეჯამება: გეგმა, ფასი, როდის მთავრდება პირველი პერიოდი (საცდელის დღეები რჩება!)
- [ ] `402` შეცდომები (`CARD_DECLINED`, `INSUFFICIENT_FUNDS`...) — გასაგები შეტყობინება ფორმასთან
- [ ] ღილაკი გადახდისას `disabled` + loader (ორმაგი გადახდა არ უნდა მოხდეს!)
- [ ] წარმატების ეკრანი: ინვოისის ნომერი, თანხა, ბარათის ბოლო 4 ციფრი, პერიოდი

### 4.4 🟢 კითხვა

**US-8. როგორც გამომწერს, მინდა წიგნის ბრაუზერში კითხვა.**
- [ ] `GET /api/books/{id}/read` → `url` → PDF-ის ჩვენება (`<iframe>` ან **PDF.js** — ეს უკეთესია)
- [ ] ფრაგმენტის რეჟიმი: `previewUrl` + ბანერი „გამოიწერე, რომ მთლიანად წაიკითხო“
- [ ] `402 SUBSCRIPTION_REQUIRED` → paywall და არა „ცარიელი გვერდი“

### 4.5 🟡 გაფართოებული (მაღალი ქულისთვის)

**US-9. ჩემი ბიბლიოთეკა**
- [ ] რჩეულები: ❤ ღილაკი ბარათებზე და წიგნის გვერდზე; optimistic update (ჯერ UI, მერე მოთხოვნა, შეცდომისას დაბრუნება)
- [ ] „ვკითხულობ“: პროგრესის ზოლი და „გაგრძელება“ ღილაკი (გახსნა `lastPage`-ზე)
- [ ] „წაკითხული“ სია
- [ ] პროგრესის შენახვა `PUT /api/library/progress/{id}` — debounce-ით (PDF.js-ის შემთხვევაში)

**US-10. შეფასებები**
- [ ] სია პაგინაციით და სორტირებით
- [ ] ვარსკვლავებით შეფასების ფორმა (1–5) + კომენტარი
- [ ] საკუთარი შეფასების რედაქტირება/წაშლა; `409 ALREADY_REVIEWED`-ის სწორი დამუშავება

**US-11. ანგარიში და გამოწერის მართვა**
- [ ] პროფილის რედაქტირება; ავატარის ატვირთვა (`FormData`)

## 6. ტექნიკური მოთხოვნები

1. **ფრეიმვორკი** — თქვენი არჩევანი: React, Angular, Vue, Svelte ან vanilla JS. TypeScript — მისასალმებელია.
2. **როუტინგი** — თითოეულ გვერდს საკუთარი URL (`/books/12`, `/account/payments`); გვერდის განახლება არ უნდა „ტეხავდეს“ აპლიკაციას.
3. **API კლიენტი** — ერთი ადგილი (სერვისი/ჰუკი/interceptor), სადაც ემატება `X-API-KEY`, `Authorization`, `Accept-Language` და მუშავდება შეცდომები. **კომპონენტებში `fetch('https://...')`-ის გაბნევა არ ითვლება.**
4. **კონფიგურაცია** — Base URL და API გასაღები `.env`-ში (`.env.example` — რეპოზიტორიაში, `.env` — `.gitignore`-ში).
5. **Responsive** — 360px-დან 1440px-მდე; ტელეფონზე სრულად გამოსაყენებელი (განსაკუთრებით კატალოგი და მკითხველი).
6. **უსაფრთხოება** — API-დან მიღებული ტექსტი არასოდეს ჩასვათ `innerHTML`/`dangerouslySetInnerHTML`/`[innerHTML]`-ით; ბარათის მონაცემები არსად შეინახოთ.
7. **კოდის ხარისხი** — კომპონენტებად დაყოფა, გასაგები სახელები, ESLint/Prettier, მცირე და აზრიანი commit-ები.
8. **Git** — საჯარო რეპოზიტორია; `README.md` სქრინშოტებით, გაშვების ინსტრუქციით და deploy-ის ბმულით.

## 11. ხშირად დასმული კითხვები

**შემიძლია React-ის ნაცვლად Angular/Vue?** კი. მოთხოვნები ფრეიმვორკისგან დამოუკიდებელია.

**სადემონსტრაციო საიტის კოდის კოპირება შეიძლება?** არა — თქვენ თავად უნდა დაწეროთ. საიტი გვიჩვენებს, *რა* უნდა მუშაობდეს და API-ს *როგორ* ვიყენებთ (API პანელი), და არა *როგორი* უნდა იყოს კოდი.

**ვერიფიკაციის წერილი არ მოდის!** sandbox-ში წერილები ნამდვილ ფოსტაში არ მიდის — ნახეთ `GET /api/sandbox/inbox?email=...` (ან სადემონსტრაციო საიტის API პანელში → „ინბოქსი“).

**პირველი ანგარიში ადმინი აღმოჩნდა — ეს ბაგია?** არა: sandbox-ის პირველი მომხმარებელი ადმინია. ჩვეულებრივი მომხმარებლის შესამოწმებლად შექმენით მეორე ანგარიში.

**საცდელი პერიოდი უკვე გამოვიყენე, თავიდან როგორ ვცადო?** `POST /api/sandbox/reset-subscription` — ან ახალი ანგარიში.

**7 დღე უნდა ველოდო, რომ საცდელი დასრულდეს?** არა: `POST /api/sandbox/time-travel { "days": 8 }`.

**ნამდვილი ბარათით რა მოხდება?** API მას არ მიიღებს (`TEST_CARD_REQUIRED`) — და არც უნდა შეიყვანოთ ნამდვილი ბარათის მონაცემები სასწავლო პროექტში.

**PDF როგორ ვაჩვენო?** უმარტივესი: `<iframe src={url}>`. უკეთესი: PDF.js — მაშინ იცით მიმდინარე გვერდი და პროგრესის შენახვა შეგიძლიათ.

**CORS-ის შეცდომა მაქვს.** API ყველა origin-ს უშვებს. თუ მაინც CORS შეცდომაა, ყველაზე ხშირად მიზეზი არის არასწორი URL (404) ან სერვერის შეცდომა — Network ტაბში ნახეთ ნამდვილი პასუხი.
